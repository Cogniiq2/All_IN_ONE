# Runbook — the BoLaGio STAGING workflows on the shared n8n instance

For the staging live test (`docs/staging-live-test.md`): automatic booking
confirmation e-mails from staging, on the n8n instance that also runs the
Cogniiq automations, without touching any of them.

## 1. What is imported, and why these

The website/backend is the source of truth. It renders every e-mail, decides
whether it is due and records it in the delivery ledger; n8n only carries it.
The endpoints n8n can call (`/api/internal/outbox`, `/api/internal/messages`,
`/api/internal/health`, `/api/internal/booking`) can claim and acknowledge
events, prepare and record a message, and read — none can confirm, cancel or
change a booking, and n8n holds no Beds24 or PayPal credential.

| File (`n8n/workflows-staging/`) | Workflow | Needed for the e-mail test | Activate |
|---|---|---|---|
| `bolagio-staging-outbox-event-pump.json` | BoLaGio STAGING · Outbox Event Pump | yes — claims `booking.confirmed` every 60 s | yes (step 6) |
| `bolagio-staging-guest-message.json` | BoLaGio STAGING · Guest Message | yes — prepare → SMTP → record | no (called by the pump) |
| `bolagio-staging-error-handler.json` | BoLaGio STAGING · Error Handler | yes — records failures | yes (step 4) |
| `bolagio-staging-operational-alert.json` | BoLaGio STAGING · Operational Alert | called by the pump for alert events | no |
| `bolagio-staging-cleaning-routing.json` | BoLaGio STAGING · Cleaning Routing | called by the pump; transport stays `disabled` | no |
| `bolagio-staging-health-poll.json` | BoLaGio STAGING · Health Poll | optional | optional |

Generated by `node n8n/build-staging.mjs` from the production package, so the
logic is identical. What differs, and is asserted by
`tests/n8n-workflows.test.ts`:

| | Production package | Staging copies |
|---|---|---|
| names | `BoLaGio · …` | `BoLaGio STAGING · …` |
| workflow ids | e.g. `FEBPCqRDXnNsGHQt` | new ids derived from the new names |
| variables | `$env.BOLAGIO_*` | `$env.BOLAGIO_STAGING_*` |
| SMTP credential | `BoLaGio SMTP` | `BoLaGio STAGING SMTP` |
| outbox worker id | `n8n-bolagio` | `n8n-bolagio-staging` |
| tag | `bolagio` | `bolagio-staging` |
| state on import | inactive | inactive |

No staging workflow can read a production variable, call a production
workflow, use the production credential or report to the production error
handler, and none references anything of Cogniiq's. The production package is
**not** imported by this runbook.

**Exactly once.** The pump may deliver an event more than once; the backend's
delivery ledger (`bolagio_message_deliveries`, unique
`<reference>:booking_confirmation:1`) turns that into one e-mail. `prepare`
refuses unless the booking is `confirmed`, the payment is `paid` **and** the
Beds24 confirmation was read back (`beds24_verified_at`) — so n8n cannot send
early whatever it receives.

## 2. The one disruptive step, stated plainly

n8n reads `$env` at process start. Adding the `BOLAGIO_STAGING_*` variables
means **one restart of the shared n8n instance** — every Cogniiq workflow pauses
for the restart (typically under a minute; schedules resume, webhooks sent
during the restart are refused by n8n and retried only if the sender retries).
Do it in a quiet moment. Nothing else in this runbook needs a restart; later
transport changes do (e.g. switching `MESSAGING_TRANSPORT`).

If no restart of the shared instance is acceptable, the alternative is a
separate staging n8n (Docker on any host): import the **production** package
there with `BOLAGIO_*` variables pointing at staging. Same result, zero contact
with the Cogniiq instance.

## 3. Values to prepare (never paste them into a chat)

| Where | Name | Value |
|---|---|---|
| Cloudflare → `bolagio-staging` → Settings → Variables and Secrets (type **Secret**) | `N8N_INTERNAL_SECRET` | a new random string, ≥ 32 characters (`openssl rand -hex 32`) |
| same | `MESSAGING_CONTACT_EMAIL` | the reply address guests see in the e-mail |
| n8n host environment | `BOLAGIO_STAGING_N8N_INTERNAL_SECRET` | **the same** string as `N8N_INTERNAL_SECRET` |
| n8n host environment | `BOLAGIO_STAGING_SITE_URL` | `https://bolagio-staging.popovic-lazar0603.workers.dev` (no trailing slash) |
| n8n host environment | `BOLAGIO_STAGING_ENVIRONMENT` | `staging` |
| n8n host environment | `BOLAGIO_STAGING_MESSAGING_TRANSPORT` | `disabled` first; `smtp` for the test (step 7) |
| n8n host environment | `BOLAGIO_STAGING_MAIL_FROM` | the sender, e.g. `BoLaGio Staging <staging@…>` — must be allowed by the SMTP account |
| n8n host environment | `BOLAGIO_STAGING_ALERT_TRANSPORT`, `BOLAGIO_STAGING_CLEANING_TRANSPORT` | `disabled` |
| n8n → Credentials → New → **SMTP** | name exactly `BoLaGio STAGING SMTP` | a sending account that is not a Cogniiq mailbox (host, port, user, app password) |

Instance settings the Code nodes need (check, do not change if already so):
`N8N_BLOCK_ENV_ACCESS_IN_NODE` is not `true`, and `NODE_FUNCTION_ALLOW_BUILTIN`
includes `crypto`. If either must change, that is a change to the shared
instance's security settings — decide it consciously; it affects every
workflow there.

## 4. Steps

1. Cloudflare: add `N8N_INTERNAL_SECRET` and `MESSAGING_CONTACT_EMAIL` to
   `bolagio-staging` (encrypted). Deploy.
2. n8n: create the credential **BoLaGio STAGING SMTP** (Credentials → Add
   credential → SMTP). Use *Test* in the credential dialog only if it sends
   nothing to a guest.
3. n8n host: add the `BOLAGIO_STAGING_*` variables with
   `MESSAGING_TRANSPORT=disabled`; restart n8n once (see §2).
4. Import, inactive, ids preserved — on the n8n host, from a checkout of
   branch `claude/bolagio-success-screens`:
   `n8n import:workflow --separate --input=n8n/workflows-staging`
   Check in the UI: six workflows `BoLaGio STAGING · …`, tag
   `bolagio-staging`, all inactive, Execute Workflow nodes show
   `BoLaGio STAGING · …` targets, Send Email nodes show
   `BoLaGio STAGING SMTP`. (UI import works too, but then re-select every
   Execute Workflow target and error workflow by hand — `README.md` §4b.)
   Activate **BoLaGio STAGING · Error Handler**.
5. *BoLaGio STAGING · Outbox Event Pump → Test workflow* once. Expected: it
   runs green and claims 0 events (the outbox is empty). Staging records the
   heartbeat `n8n · last outbox claim` = `n8n-bolagio-staging: 0`.
6. Activate the pump. The preflight (Control → System → Test bookings) now
   shows *Staging n8n pump is polling the outbox* as **Pass**.
7. Immediately before the live test: set
   `BOLAGIO_STAGING_MESSAGING_TRANSPORT=smtp`, restart n8n (second and last
   restart).

## 5. Rollback

Deactivate **BoLaGio STAGING · Outbox Event Pump**. Events wait in the
outbox; nothing is lost or sent. To remove the package entirely, delete the
six `BoLaGio STAGING · …` workflows and the credential, and remove the
`BOLAGIO_STAGING_*` variables at the next convenient restart. Nothing of
Cogniiq's or of the production package was changed.
